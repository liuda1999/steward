# 云端外援调用规则

> 把这份文件的内容贴进宿主的规则文件：Claude Code 用 `CLAUDE.md`，opencode 用 `AGENTS.md`，Codex CLI 用 `AGENTS.md`，Cursor 用 `.cursorrules`，Cline / Roo / Kilo 用各自的 Custom Instructions。
>
> 原因：`mcp-config.json` 里的 `DAILY_LIMIT` 只能卡**次数**，卡不住**场景**。什么活该上云、什么活不该，得靠这份规则在宿主侧拦。

---

## 铁律

**默认本地完成。** 达不到下方 L1 / L2 判据的，一律本地闭环，禁止调用任何云端 lane。

你的本地脑是 30B MoE Q4 + 256K 上下文。绝大多数"复杂任务"它其实扛得住 —— 只有真正需要**跨系统取舍的架构判断**、或**本地已经转不出来的根因**才值得花钱。

---

## 三级分流

### L0 本地闭环 —— 约 85–90%

判据：目标明确、改动范围已知、结果可验证。
覆盖：单文件修改、写测试、重构、补文档、已知报错修复、批量替换、代码阅读、常规调优。
动作：**完全不经过外援。**

### L1 云端速判 —— 约 8–10%

判据：范围清楚但拿不准，或已卡住但仍能一句话描述清楚。
覆盖：两方案二选一、报错的可能根因、某个 API 的正确用法、边界情况清单、快速 sanity check。
动作：`ask_cascade` 或 `ask_best`，**一句话提问，不用 BRIEF 委托单。**
上限：一个问题，一次往返。

### L2 正式委托 —— 约 2–5%，稀有

判据（命中任一即可）：不可逆操作 / 跨系统架构 / 本地两轮以上未收敛 / 需要多方案横向取舍。
覆盖：全新架构设计、疑难根因分析、数据迁移评审、技术选型决策。
动作：按 `HANDOFF-PROTOCOL.md` 写 BRIEF，要求返回结构化交付物。

### 升级链

L0 改两次仍不通过 → L1。L1 拿了建议仍失败 → L2。
L2 同一问题最多 2 次往返，超了降级本地 + 人工。

---

## 上云前必须做

1. **本地先完整跑一遍。** 把已有结论、尝试过的路径、报错原文全部记下来，一起打包给云端。没有前置努力就不许上云。（L1 速判可豁免这条，但必须能一句话说清卡点。）
2. **一次问清。** 你本地有 256K 上下文，打包得起 —— 问题、上下文、约束、期望输出格式一次性给全。一次问透比来回三轮便宜得多。
3. **脱敏。** 密钥、内网地址、客户数据、业务敏感字段，先剔除再发。
4. **按 `HANDOFF-PROTOCOL.md` 写委托单。** 上行 BRIEF、下行四套交付模板（PLAN / VERDICT / REVIEW / DECISION），字段名固定。不写散文、不复述背景。

---

## 上云后必须做

1. **云端产出只当"设计稿"和"判断"，落地执行一律回本地。** 你才是执行者。
2. **拿回方案后本地拆解成步骤自己跑。** 不允许边跑边反复问 —— 这是配额杀手。
3. **追问走同一个 thread id。** 复用会话线程，禁止开新会话重述背景。
4. **同一问题最多 2 次往返。** 超了就降级：本地方案 + 打标记交由人工。

---

## 配额纪律

- 每日云端调用上限由 `CLI_BRIDGE_MYCLOUD_DAILY_LIMIT` 强制（默认配的是 5 次/天）。
- **用尽即停。不绕过、不换 lane 绕行、不改配置续命。**
- 配额用尽后剩下的活走本地。跑一周看看实际够不够，再决定是调到 3 还是 8 —— 宁紧勿松。

---

## 推荐的调用姿势

| 场景 | 层级 | 动作 |
|---|---|---|
| 常规改动 / 执行 / 重复劳动 | L0 | 宿主自己干，完全不经过外援 |
| 拿不准要不要上云 | L0→L1 | `ask_cascade` —— 便宜→强，本地能过就不花钱 |
| 一句话能问清的卡点 | L1 | `ask_best`，一次问答，不开委托单 |
| 需要多方意见 | L1 | `ask_all` 跑免费 lane 看 disagreement score，分歧大再考虑付费 |
| 架构设计 / 疑难根因 / 不可逆评审 | L2 | 按 `HANDOFF-PROTOCOL.md` 写 BRIEF，一次给全 |

## 为什么放弃第一代

第一代把「要不要花钱」的判断放在**宿主侧的规则文件**里，靠本地模型自觉遵守；配额只能数次数，卡不住场景。

问题是：模型看到的是自然语言规则，它可以选择性遵守，而且没有办法在工具层拦住一次不该发生的调用。真正需要的是**模型自决 + 网关硬拦**——模型可以判断"我拿不准"，但"能不能花这次钱"必须由网关数着。

这个结论现在由 `steward/guard.py` 落地：四道配额闸 + 一道委托质量闸，全部在请求路径上，不依赖模型配合。

## 为什么放弃 "cloudbridge" 这个名字

第二代叫 `cloudbridge`，只说了"连着云端"。但它实际做的是预算、窗口、存档三件管家活，跟"桥"已经没关系了。所以改名为 `steward`。

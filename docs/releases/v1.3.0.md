# steward v1.3.0

**把两个看不懂的数讲清楚，并且让它们在控制台里可见可改。**

起因是三个问题：两个槽位的模型标识长得一样、`裁到预算的 0.65` 是什么意思、进阶模型慢的时候默认等多久、会不会白花额度。这三个问题背后是同一个毛病——**关键参数藏在 YAML 里，界面上看不见**。

---

## 一、两个槽位会不会搞混

**先说结论：你看到的一样，是因为那是我起测试用的假配置。**

我为了验证控制台，把两个槽位都指向了同一个假上游（`stub`），模型标识自然写的是同一个。真实的配置里它们是两回事：

| 槽位 | 常见填法 | 例子 |
|---|---|---|
| 基础模型 | 本地部署的模型 | `qwen3:8b`（Ollama）、`/models/qwen3-30b.gguf`（llama.cpp） |
| 进阶模型 | 云端 API | `gpt-4o-mini`、`claude-3-5-haiku` |

**同名也不会串。** 两个槽位的地址、模型名、超时各自独立，网关按槽位路由，不会因为名字一样就走错。

不过你的担心是对的，所以我加了两道防呆：

1. **控制台顶部状态条**分开显示两个槽位（基础绿、进阶红），并显示各自的超时；
2. **两个槽位填得完全一样时给出提示**：

```
两个槽位指向同一个模型（qwen3:8b @ http://127.0.0.1:11434/v1）：进阶调用会打到
和基础模型一样的端点。用本地模型替代云端时这是有意的，否则多半是复制粘贴
```

模型标识的输入框也加了提示，说明本地和云端要的格式不一样。

## 二、`裁到预算的 0.65` 是什么

裁剪不是「正好塞进窗口」，而是**砍到窗口的 65%**，留 35% 余量：

```
可用窗口 × usable_ratio(0.85) − 输出预留 − 安全余量 × 学到的收缩系数 = 预算
预算 × target_ratio(0.65)                                          = 裁剪目标
```

**为什么不砍到刚好装下？** 下一轮还会长——模型的回答、工具结果都要进窗口。砍到 100% 的话下一轮立刻又超，于是又裁一次；而每次裁剪都会让 llama.cpp 的**前缀缓存失效**，那一大段历史要重新 prefill（实测约 1300 tok/s）。留 35% 余量，几轮之内不用再裁。

配套的 `min_clear_tokens`（默认 8000）：一次裁剪至少要清出这么多 token 才值得动，否则宁可留着——**不裁剪，缓存还在**。所以策略是「少裁但裁到位」。

| target_ratio | 效果 |
|---|---|
| 0.75~0.85 | 裁得更浅更勤，每次重算的少，但缓存失效次数多 |
| 0.5 左右 | 一次砍得狠，两次裁剪之间撑得久，但每次重算的量大 |

## 三、进阶模型慢的时候等多久

| 位置 | 默认 |
|---|---|
| 基础模型 `base.timeout_s` | **600 秒**（本地 30B 长上下文首字慢，给足） |
| 进阶模型 `advanced.timeout_s` | **120 秒**（云端 API 的常规上限） |
| 连接超时 | **15 秒**（握手阶段就该失败，不该干等） |
| 骨架提炼 | 30 秒（内部调用，不影响主请求） |

**超时会不会白花额度？分两种情况：**

| 情况 | 报错 | 额度 |
|---|---|---|
| 根本没连上（服务没启动、地址写错） | 立刻 `connect: …` | **退回**（请求没送到上游） |
| 连上了但没等到结果（模型太慢） | 等满超时才 `timeout` | **不退**（上游可能已在生成、已在计费） |

所以「一不小心超时」不会白花额度，只会在已经花钱的情况下白等。

**现在你能自己校准了：**

- 控制台里两个槽位的超时都能直接改，状态条上一直显示着；
- 响应头新增 `X-Steward-Cloud-Ms`——这一轮进阶模型实际花了多少毫秒（实测：慢的那次 5000ms，正常那次 1000ms）。

## 四、顺带修掉一个会误导人的 bug

测超时的时候发现：**机器上设了 `HTTP_PROXY` 时，本机地址也会被送给代理。**

`httpx` 默认 `trust_env=True`。代理转发不动的时候，**连接失败被伪装成超时**——你看到的是「模型太慢」，实际是「模型根本没启动」。实测一个没人听的端口：

```
修复前：等满 2 秒 → timeout
修复后：立刻 → connect: All connection attempts failed
```

规则改成：

| 地址 | 走不走代理 |
|---|---|
| 回环、RFC1918 私网、`.local` / `.localhost` / `.localdomain` | **直连** |
| 公网地址 | 照旧走代理（企业网关与 CA 都不受影响） |

实现在 `steward/netpolicy.py`。

## 五、控制台另一个静默失效

写测试时发现：控制台**只能改配置里已经存在的键**。旧配置如果没有 `timeout_s` 这一行，界面上填了超时却毫无反应——用户只能靠猜。

现在段里缺这个键就**补一行**（缩进跟同段一致），而不是静默放弃。补出来的内容同样会经过写盘前的校验。

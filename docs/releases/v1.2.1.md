# steward v1.2.1

**修一个让你进不去控制台的 bug。** v1.2.0 的控制台在预览面板、嵌入式工具这类环境里登录会失败——不是你操作的问题，是我的实现只认 cookie，而那些环境存不了 cookie。

---

## 症状

页面能打开（`GET /` 返回 200），但一提交口令就失败：

```
来源校验失败：只接受本页面发起的请求
```

在普通浏览器标签页里是好的，在沙箱 iframe 里必现。

## 两个原因

**一、来源判定太严。**

原实现只认「`Origin` 的 netloc 等于 `Host` 头」。但这两者不等的正当访问有两类：

| 场景 | Origin | 为什么不等 |
|---|---|---|
| 沙箱 iframe（预览面板、嵌入式工具） | `null` | 页面处在不透明来源里，浏览器没有真实主机名 |
| 经本地代理访问 | 代理的主机名 | 代理重写了 `Host` 头 |

两种都被判成跨站 → 403。

**二、更致命：认证只靠 cookie。**

就算来源判定放过，cookie 也靠不住：

- 沙箱 iframe 里页面处在不透明来源，**浏览器不允许它存 cookie**；
- `SameSite=Strict` 的 cookie **不跨站发送**，而预览面板的页面与它代理的后端在浏览器眼里是两个站点。

所以即使登录那一步返回 200，之后每一个请求都会 401。

## 改法

**认证换成自定义请求头。** 页面把口令放在 `X-Console-Token` 里发，每个请求都带：

```js
if (TOKEN) opt.headers["X-Console-Token"] = TOKEN;
```

这反而是**更硬**的防跨站手段：自定义头跨域必须先过 CORS 预检，而我们不发任何 CORS 头，浏览器会在预检阶段就拦掉请求。cookie 保留下来，只在普通浏览器里当便利（刷新页面不用重输口令）。

**来源判定区分「跨站」和「不是同源」。** 现在放行三类：

| 放行 | 理由 |
|---|---|
| 同源（`Origin` 的 netloc == `Host` 头） | 本来就该放 |
| `null` | 沙箱 iframe 的不透明来源；真正的凭证在请求头里，外站拿不到 |
| 回环地址 + 我们的端口 | 经本地代理访问本机 |

其余一律 403。真正要挡的 `https://evil.example` 改不成上面任何一种——它的 `Origin` 由浏览器写死，页面自己设不了。

## 验证

```
登录（各种来源）                  状态读取                写配置
正常同源    → 200            请求头 + Origin:null → 200   外站 Origin + 正确口令 → 403
沙箱 iframe → 200            cookie 方式也仍然可用        无 Origin（脚本）→ 200
本地代理    → 200
外站        → 403
无 Origin   → 200
```

测试 381 → **387**（控制台 27 → 33）。新增用例覆盖：沙箱 `null` 来源、本地代理来源、请求头认证、请求头写操作、错误请求头被拒、以及「外站即使知道口令也发不动」。

回归注入验证：把 `null` 来源改回拒绝 → 测试立刻变红。

## 升级

```bash
git pull
python -m steward serve
```

无需改配置。口令没变（还在 `state/console.token`），但如果你想换一个新的，删掉那个文件重启即可。

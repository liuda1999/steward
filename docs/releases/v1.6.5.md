# steward v1.6.5

**两个「用起来别扭」的地方：模型列表莫名其妙多出两个，以及 key 签发完就找不到了。**

补丁发布，不改配置结构、不改协议。

---

## 一、`/v1/models` 返回三个模型

客户端拿到的是：

```json
["auto", "local", "steward"]
```

原因是模板里带了默认别名：

```yaml
public_model: auto
model_aliases: [local, steward]     # ← 出厂就带两个
```

网关本身只有一个模型（由 `base` 槽位决定），别名只是给「客户端非要某个模型名」的场景留的口子。把它做成出厂默认，结果就是每个新装的实例都显示三个模型，用户以为背后跑了三套。

**修复**：模板改成 `model_aliases: []`，默认只返回 `public_model` 一个。需要别名的人自己加，功能没删。

> 已经装过的实例：`config.yaml` 是首次启动时生成的，不会自动跟着模板变。手动把那一行改成 `model_aliases: []` 再重启即可。

## 二、key 签发完就找不到

项目 key 的规则是**只存 sha256，不存明文**——签发时显示一次，之后任何地方都取不回来。这是有意的（`state/keys.json` 泄露也不等于 key 泄露），但控制台之前只做到「显示一次」，没做到「好拿」：

- 签发结果只有一段 `<code>`，没有复制按钮
- key 列表只有「吊销」，想换一把得自己再去点「签发」
- 启动横幅只说 key 文件在哪，不说忘了怎么办

**修复**：

- 签发结果加**一键复制**；局域网 IP 不是安全上下文、`navigator.clipboard` 不可用时，自动退回到「选中文本 + 提示按 Ctrl+C」
- key 列表每条加**「重新签发」**：吊销旧的、按原标签签一把新的，明文同样只显示一次
- 启动横幅在已有 key 时补一句：`忘了明文就去控制台「项目 key」：签发一把新的，或对旧条目点「重新签发」`
- 控制台说明改成「忘了就重新签发」，不再让人以为能找回来

## 三、验证

| 场景 | 结果 |
|---|---|
| 默认配置 `/v1/models` | `["auto"]` |
| 显式配 `model_aliases: [local, steward]` | `["auto", "local", "steward"]`，功能保留 |
| 控制台中英字典 | 新增 5 条，两边一致（既有测试自动覆盖） |
| 全量测试 | **488 通过 / 1 跳过** |

新增测试：默认只列一个模型、显式别名仍生效、模板不再带默认别名、控制台有复制与重签入口。

## 四、升级

- 替换代码后重启
- 如果你希望只看到一个模型，把 `config.yaml` 的 `model_aliases` 改成 `[]`
- 已经签发过的 key 不受影响；想换 key 用「重新签发」

# steward v1.6.2

**v1.6.1 让启动器会回退到 `python`，但如果 PATH 上根本没有可用的 Python，它仍然只会说一句「No Python found」。这一版把「找 Python」补完：PATH 上没有，就去常见安装目录里找。**

补丁发布，不改配置、不改协议、不迁移数据。

---

## 一、问题：PATH 上没有可用 Python

v1.6.1 的探测顺序是 `PYTHON → .venv → py -3 → python → python3`，全部只查 PATH。

真实场景是：机器上确实装了 Python，但**没在 PATH 上**；PATH 上的 `python` / `python3` 只是微软商店的占位程序（执行时返回 9009，什么也不做）。于是三个探测全部失败，脚本报：

```
[env] No Python found on PATH. Install Python 3.11+ from
https://www.python.org/downloads/ and tick "Add python.exe to PATH".
```

用户看着「已经装了 Python」的电脑，被要求再装一遍。

## 二、修复：补一步目录扫描

PATH 探测全部失败后，脚本再扫四个位置，每个候选都实际执行一次 `-c "import sys"`，第一个能跑的胜出：

```
%LOCALAPPDATA%\Programs\Python\Python3*      ← python.org 的用户级安装（最常见）
%ProgramFiles%\Python3*                       ← 全机安装
C:\Python3*                                   ← 老式安装位置
%USERPROFILE%\.workbuddy\binaries\python\versions\*  ← WorkBuddy 自带的 Python
```

顺带修了两个相关问题：

- **路径与命令的引号**：`py -3` 是「命令 + 参数」，不能加引号；`C:\...\python.exe` 是路径，必须加引号。现在按「第二个字符是不是 `:`」判断，两种情况都对。
- **错误提示可执行**：找不到时不再只让人去官网，而是直接给出 `set PYTHON=C:\path\to\python.exe` 这条命令。

## 三、验证

模拟用户的真实 PATH（只留系统目录和微软商店占位程序），其余环境不变：

| 场景 | 结果 |
|---|---|
| PATH 无可用 Python，`--check` | 扫描命中可用解释器，四步检查全过 |
| PATH 无可用 Python，真实启动 | 健康检查 200、控制台 200、端口干净释放、日志 0 异常 |
| 正常 PATH | 仍然走 `python3`，行为不变 |
| 显式 `PYTHON` | 优先使用指定的解释器 |
| `start.bat` 编码 | 纯 ASCII（cmd 代码页不会把中文变乱码） |
| 全量测试 | **480 通过 / 1 跳过** |

新增回归测试 `test_start_bat_scans_common_install_dirs`：锁住四个扫描位置、`:scan` 兜底、以及「盘符路径加引号、`py -3` 不加」这条规则。

## 四、升级

- 直接替换代码，无需改 `config.yaml`
- Windows 用户重新执行 `scripts\start.bat` 即可，不再需要手动设 `PYTHON`
- 长期建议：装一份独立的 Python 3.11+ 并勾选 Add to PATH，不要长期依赖编辑器/工具自带的解释器（它可能随工具升级被替换）

# steward v1.6.0

**控制台从「能用」变成「像个产品」：中英双语、重做的登录页、项目 logo。顺带修掉三个只有真机跑才会暴露的 bug，以及一段把用户吓到的启动噪音。**

起因是一句话：「项目的 Web UI 界面太丑了，颜色也难看。」附图是暗色模式下的一张登录页——一个 420px 的表单丢在 12vh 下面，四周全是空白，配色接近黑白。

---

## 一、控制台双语

界面原先只有中文，英文读者打开控制台只能猜。

- 静态文案走 `data-i18n` 标记，共 69 处，配一张 zh/en 字典
- 右上角 `EN / 中文` 一键切换，选择存 `localStorage`，首次打开跟随浏览器语言
- **动态文案也覆盖**：状态 chips、密钥表、测试连接结果、保存/重启提示、保存结果横幅
- 服务端返回的校验文案（口令错误、来源校验、配置不能启动…）做了常见映射，英文界面不会蹦出中文
- 保存横幅在切语言时会重绘，不会留着另一半语言的残影

字典不是「记得改另一边」——测试会比对中英条目数是否一致、页面引用的每个键是否都存在。

## 二、界面重做

登录页原来是全屏空白里一个小表单。现在：

- **整屏两栏**：左边品牌区（logo、标题、三条能力点），右边浮起的登录卡；窄屏自动堆叠，手机上隐藏能力点
- **新配色**：靛蓝 `#3b5bdb` → 青绿 `#0ea5a4` 渐变作主色，中性色偏暖，亮/暗各一套；语义色（本地绿、云端红）保留给状态标签
- **组件统一**：渐变主按钮、10px 输入框配柔性聚焦环、14px 卡片、毛玻璃吸顶页眉
- **项目 logo**：256×256 PNG，页眉与 favicon 共用，随 wheel 一起打包

主界面布局没动——老用户不会找不到东西，只是看起来终于像成品了。

## 三、真机跑出来的三个 bug

这三个都不是读代码能发现的，全是拿真实模型跑出来的。

### 3.1 「测试连接」不认已保存的 key

输入框留空的意思是「不改」，但测试连接拿着**空 key** 去探上游。云端槽位必然 401，而界面上明明写着「已设置」——用户只会以为自己地址填错了。

现在留空会回退到已保存的 key，并有回归用例盯着。

### 3.2 保存提示被自己抹掉

`render()` 每次刷新都会清空 `#saveMsg`。保存成功后正好会 refresh 一次，于是「已保存，等待重启」一闪就没，用户不知道到底存没存。

### 3.3 改动计数造假

`apply_changes()` 把**提交的每个字段**都算作改动，从不与旧值比较。界面是整份表单提交，所以改一个数字，提示「共 22 项」——看着像配置被改乱了，而且没改的行也被重写一遍。

现在按语义比对（`"600"` 和 `600` 算同一个），无改动时文件一个字节都不动。

## 四、启动噪音

Windows 上浏览器刷新或关页面时，asyncio 的 proactor 会在 `_call_connection_lost` 里抛 `ConnectionResetError`，默认处理器把它当未捕获异常，往终端打一整段 Traceback：

```
Exception in callback _ProactorBasePipeTransport._call_connection_lost()
...
ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接。
```

请求早就 200 返回完了，但看到 Traceback 的人第一反应是进程崩了。现在只吞「连接被对端重置/中止」这一类，其它异常照常交给默认处理器——有测试保证真错误不会被一起吞掉。

## 六、升级

- 直接替换代码后重启即可，**配置文件无需改动**
- 新版控制台不需要迁移，浏览器刷新就是新界面
- 语言选择存在浏览器本地，清掉 `localStorage` 就恢复跟随系统

# steward v1.6.7

**给仓库补上最小 CI：一个 workflow、六个 job、真实状态徽章。顺带把那条从没在 Linux 上跑过的端到端启动测试修到能跑。**

补丁发布：不改动网关行为、配置格式和对外协议，只动仓库层的 CI、文档与测试。

---

## 一、为什么补 CI

仓库已经有 490 个用例，但一直靠本机手跑：只有 Windows + Python 3.13 这一套环境，而 `pyproject.toml` 声明支持 3.11/3.12/3.13，还同时提供 Linux 和 Windows 两套启动脚本。更直接的问题是首页那个 `tests-490 passing` 是**手写徽章**，不反映任何真实运行——每加一个用例就得手工改一次数字，漏改就是对外虚报。

所以补的是最小门禁，不是一套发布流水线：

- 触发：`push(main)` / `pull_request` / `workflow_dispatch`
- 矩阵：`ubuntu-latest`、`windows-latest` × Python 3.11 / 3.12 / 3.13，共 6 个 job
- 步骤：checkout → setup-python → 装 `requirements.txt` + pytest + `pip install -e .` → `pytest -q`
- **不构建、不发版、不持有任何令牌**；发布仍由 `scripts/publish.py` 在本地手工完成

两份 README 顶部的手写数字换成 Actions 真实徽章，指向 `tests.yml`。以后测试数再变，README 不用动。

## 二、新增的回归测试

`tests/test_ci.py`，8 条，锁住 CI 配置本身：

- workflow 存在、能被 YAML 解析、三个触发条件齐全
- 矩阵里的 Python 版本与 `pyproject.toml` 的 classifiers 完全一致，两个平台都在
- 装的是项目自己的依赖与包，跑的是全量测试
- workflow 里不出现 `secrets.`、令牌名、发布脚本和发版步骤
- 两份 README 都指向真实徽章，且不再有 `badge/tests-NNN` 这种写死的数字

写的时候这条测试先抓到一次误伤：它把 workflow **注释**里提到的脚本名当成了发布步骤。改成只检查配置行，注释说明给读的人看，不算步骤。

## 三、顺带修掉的 Linux 端到端测试

`test_start_script_runs_end_to_end` 在 Windows 上一直被 skip，也就是说 CI 上线后它会是第一次真正执行。检查发现四个问题，都会让 Linux job 必红：

| 问题 | 原因 | 修法 |
|---|---|---|
| 配置断言永远落空 | `start.sh` 会 `cd` 到仓库根，配置生成在仓库里，而测试检查的是临时目录 | 显式传 `--config <临时目录>/config.yaml` |
| 端口写死 27431 | CI 上偶发占用就会误报 | 改用 `_free_port()` |
| `PYTHONHOME=""` | CPython 把空值当成已设置，找不到标准库直接退出 | 改成 `pop("PYTHONHOME", None)`，让它自己探测 |
| `/health` 走代理 | 开发机设了 `HTTP_PROXY`，回环请求被送进代理导致超时 | `httpx.Client(trust_env=False)` |

另外给 Popen 加了 `errors="replace"`（Windows 控制台可能是 GBK，别让读日志的线程先炸），失败时把启动脚本输出一起打出来——CI 日志里能分清是端口占用、依赖缺失还是脚本报错。

## 四、验证

| 场景 | 结果 |
|---|---|
| `steward start --check` | 四步全过；仅一条预期提示（两个槽位指向同一模型，是有意配置） |
| 连续三次真实启动 | 每次 `/health` 200，**日志 0 条 Traceback / ERROR**；窗口 131072（来源 `props`）、`/tokenize` 可用；进程全部清理，27418 无残留监听 |
| 全量测试 | **498 通过 / 1 跳过**（原 490 + 8 条 CI 回归） |
| 干净克隆复验 | 无 `config.yaml`、无 `state/`，同样 498 通过 / 1 跳过 |
| `start.sh --check --config <临时目录>` | 配置确实生成在指定路径，四步检查全 OK |
| workflow 结构 | YAML 解析出 3 个触发、2 个平台、3 个 Python 版本 |

**唯一没有在本机等价验证的**是 Linux job 里的那条端到端启动测试：Windows 按设计 skip，本机通过 Python 调 `bash` 又被环境的 WSL 程序黑名单拦下。已知的三个干扰源已从测试里清掉，CI 首跑会真正覆盖它；万一失败，日志现在会带出启动脚本输出。

## 五、升级

- 纯仓库层改动，**不用改 `config.yaml`、不用重启网关**；拉最新代码即可
- 徽章改为动态后，首页测试数不再需要手工维护
- CI 只对推到 GitHub 的 `main` 分支和 PR 生效；本地照旧 `python -m pytest -q`

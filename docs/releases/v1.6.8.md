## 二、Ubuntu：百分比阈值随换行漂移

```
tests/test_audit.py:675  assert abs(n_bytes - o_bytes) < o_bytes * 0.05
实际：24590 -> 25868，差 1278 字节（5.2%），刚好越过 5%
```

合并 60 个日志文件时，新版本给每份正文加一个几十字节的抬头，合计约 1.3 KB，属于设计内开销；注释里本来就写着「60 份抬头才 2 KB 量级」。但旧版正文在 Windows 上是 CRLF、在 Linux 上是 LF，本机 `o_bytes` 更大，5% 刚好够用；Linux 上正文变短，同样的固定开销就超了阈值。

改成**绝对上限 4096 字节**：这条要防的是「合并后体积失控」，不是「相对波动超过某个比例」。平台换行和临时目录路径长度都不该影响结论。

## 三、Windows runner：8.3 短路径

```
期望  C:\Users\runneradmin\AppData\Local\Temp\st-test-xxx\proj
实际  C:\Users\RUNNER~1\AppData\Local\Temp\st-test-xxx\proj
```

`tmp_path` 来自 `mkdtemp()`，GitHub 的 Windows runner 把它给成 8.3 短名（`RUNNER~1`）；测试却拿 `root.resolve()` 展开后的长路径（`runneradmin`）去比字符串。两者指向同一个目录，只是拼写不同。本机用户名没有短名，所以这条在本机永远绿。

现在两边都先 `Path(p).resolve()` 再比较，比较的是「是否同一个目录」，而不是「字符串是否一模一样」。

# steward v1.6.4

**控制台的「测试连接」每点一次就多出一块「可用模型」。** 测一次 → 点一个模型 → 再测一次，列表就叠一层；点几次叠几块。原因是新列表直接 `appendChild`，从不移除上一轮的。

补丁发布，只改前端，不改配置、不改协议。

---

## 一、问题

控制台里点「测试连接」，成功后会列出上游 `/v1/models` 返回的模型名，点一下就填进「模型标识」。这段渲染写在 `console.html`：

```js
const pick = document.createElement("div");
pick.className = "out";
pick.innerHTML = t("test.models") + d.models.map(...);
out.parentElement.appendChild(pick);      // ← 只追加，不清理
```

每点一次测试就新建一个 `div` 追加到同一个父节点下，上一块原地不动。于是：

- 第一次测试：1 块
- 点一个模型，再测一次：2 块
- 再点再测：3 块、4 块……

截图里叠了四块，每块内容一模一样。除了视觉噪音，还让人怀疑「是不是模型列表变了」。

## 二、修复

- 给列表一个稳定的 id：`pick-<slot>`（基础 / 进阶各一个）
- **每次测试开始时就按 id 移除上一轮的那块**，再走请求

这样无论成功还是失败都不会残留旧列表；失败时也不会留着上次的模型名（地址可能已经换了，旧列表反而是误导）。

```js
const stalePick = document.getElementById("pick-" + slot);
if (stalePick) stalePick.remove();
```

1. 登录控制台
2. 点「测试连接」→ 等模型列表出现
3. 点第一个模型填入
4. 再点「测试连接」，重复三轮

| 轮次 | `#pick-base` 数量 |
|---|---|
| 第 1 次 | 1 |
| 第 2 次 | 1 |
| 第 3 次 | 1 |

页面上 `[id^="pick-"]` 始终只有 1 个，**0 个 JS 异常**。截图确认只剩一块「可用模型（点一下填入）」。

新增回归测试 `test_test_connection_replaces_the_model_pick_list`：锁住「列表有稳定 id」和「测试开始先 `remove()` 旧列表」两条。全量测试 **484 通过 / 1 跳过**。

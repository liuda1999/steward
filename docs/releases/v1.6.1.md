# steward v1.6.1

**修一个「项目看起来根本没有启动方式」的 Windows bug：`scripts\start.bat` 只认 `py` 启动器，机器上没有 `py` 时窗口一闪就关。顺带把「日常启动」提到 README 最前面。**

这是一次补丁发布，不改配置、不改协议、不迁移数据。

---

## 一、问题：没有 `py` 就启动不了

`scripts\start.bat` 里写的是：

```bat
if not defined PY set "PY=py -3"
```

`py` 是 Windows 的 Python 启动器，但**它不随所有 Python 安装一起出现**——微软商店版就没有。机器上只有 `python` 时，这行会报：

```
'py' 不是内部或外部命令，也不是可运行的程序
```

脚本随即退出。双击运行时 cmd 窗口一闪就关，脚本自己的错误提示都来不及看。用户得到的信息只有「这个项目没有启动方式」。

## 二、修复：探测式回退

现在按顺序探测，用第一个**真能跑起来**的：

```
PYTHON 环境变量 → 项目 .venv → py -3 → python → python3
```

每个候选都用 `-c "import sys"` 实际执行一次，而不是只看命令存不存在。找不到任何一个时，给出三条可执行的下一步：装 Python 并勾选 Add to PATH、设置 `PYTHON`、或改用 `python3`。

探测而非硬编码有一个额外好处：测试机上恰好有一个残缺的 `python 3.13.12.old`——打印 `--version` 正常，但加载不了标准库，`python -c` 直接崩。旧脚本会选中它然后失败；新脚本的探测会跳过它，落到可用的 `python3` 上。

README 里的 CLI 示例也统一改成 `python3 -m steward start`：`python` 可能是商店占位程序或残缺安装，`python3` 在 Linux / macOS / Windows 上都更可靠。

## 三、文档：启动方式前置

原来的启动命令在「三、部署」里，前面隔了两节概念（它解决什么问题、架构）。读者找的是「怎么跑」，不是「你解决了什么」。

现在 README 第一节就是「**快速启动（日常就这一条命令）**」：

- Linux / macOS：`./scripts/start.sh`
- Windows：`scripts\start.bat`
- 首次运行自动生成 `config.yaml`，**之后每次启动都是同一条命令**，不会覆盖配置
- 明确写了：模型端点没开也能起服务和控制台，只是 `/v1` 对话会失败

英文 README 同步。`docs/DEPLOYMENT.md` 补了「之后每次启动都是同一条命令」和版本号。

## 四、验证

真机反复起停，不是只看一次启动：

| 场景 | 结果 |
|---|---|
| 同进程重启（控制台「保存并重启」）×3 | 每次 HTTP 200、健康检查 200、`--port` 覆盖在重启后仍在 |
| 冷启动 / 停止 ×3 | 每次健康 200、控制台 200、端口每次干净释放 |
| 启动日志 | 3 次 `[重启]` 标记，**0 条 Traceback / ERROR**，0 条 ConnectionReset 噪音 |
| `start.bat` 默认探测 | 无 `py`，自动跳过残缺 `python`，选中 `python3`，`--check` 通过 |
| `start.bat` 显式 `PYTHON` | 优先使用指定的解释器 |
| 全量测试 | **479 通过 / 1 跳过** |

新增两条回归测试：

- `start.bat` 必须保留 `py` / `python` / `python3` 三路探测，且不能退回无条件 `set "PY=py -3"`
- README 的「快速启动 / Quick start」必须排在「它解决什么问题」之前

## 五、升级

- 直接替换代码，无需改 `config.yaml`
- 正在运行的实例：停掉后重新执行 `scripts\start.bat`（Windows）或 `./scripts/start.sh`
- 如果你之前用 `python -m steward ...` 且一切正常，不用改；只是新文档推荐 `python3`

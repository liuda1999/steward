# steward v1.2.0

**有了控制台。** 打开 `http://127.0.0.1:27418/` 就能填两个槽位的 API、调配额、签发项目 key —— 不用再编辑 YAML，也不用记 CLI 参数。

之前的短板很具体：一个刚 clone 下来的人，面对一份带注释的配置文件，唯一能做的事是照着注释逐行改。`init` 能帮上忙，但它是一次性的向导：配错了想改，还得回到命令行。

---

## 控制台

和 API **共用同一个端口**：`/v1/*` 是给智能体的，`/` 是给人的。页面单文件、零外部依赖，断网也能打开。

| 面板 | 能改什么 |
|---|---|
| 基础 / 进阶槽位 | 地址、模型名、上游 key、协议、thinking；每个槽位带「测试连接」 |
| 配额 | 单请求上限、每日总量、最小间隔 |
| 上下文 | 窗口上限、裁剪水位、任务骨架开关 |
| 存档 / refs | 保留天数、容量上限、外发开关与白名单 |
| 监听 | 地址与端口 |
| 项目 key | 签发、查看、吊销（明文只显示一次） |

**先测再存。** 每个槽位旁边有「测试连接」，拿界面上填的、还没保存的值去探一次上游的 `/v1/models`：通了会说有多少模型、窗口多大；填错会说「连不上：…」，而不是让你存完重启才发现。

## 保存时发生的三件事

这三件事都在服务端，界面只是表单 —— 因为它们都是「做错了会留下坏状态」的操作。

**1. 按行改值，注释原样保留。**

整份重写最省事，但会把 `config.yaml` 从一份说明书变成机器产物。所以只替换目标行的值，保留缩进、空行、字段顺序和行尾注释：

```yaml
  base_url: http://127.0.0.1:27420/v1    # Ollama 默认；LM Studio 用 :1234
                ↓
  base_url: http://127.0.0.1:19280/v1    # Ollama 默认；LM Studio 用 :1234
```

**2. 密钥写进 `.env`，不进 YAML。**

`config.yaml` 里继续是 `${BASE_API_KEY}` 占位，真实值写同目录 `.env`。一份配置被复制、被贴进 issue，不该顺带带走两把上游 key。

留空表示「不改」—— 否则界面上那个空密码框每存一次都会把已有 key 抹掉。这是一个专门的标记位（`__CLEAR__`）而不是空串。

**3. 先校验再落盘。**

候选配置走一遍和启动完全相同的 `validate()`。不通过就原样保留旧文件，并说清哪一条不满足（比如「refs 开了但白名单为空」）。**能存进去却起不来的配置，比不让存更糟** —— 用户会以为改好了，直到重启才发现。

写入用临时文件 + 原子替换，中途断电不会留下半份配置。

## 进门要报口令

这个页面能改配置、能看到密钥设置没设置。摆在 `127.0.0.1` 并不等于安全，它挡不住两件事：任何网页跨站 POST 到本机（浏览器不拦这个），以及同机的其他脚本。

所以：

- **会话 cookie**：`HttpOnly` + `SameSite=Strict`，写操作再校验 `Origin` 必须同源。前者挡跨站携带，后者挡跨站构造。
- **口令限速**：连错 8 次锁一分钟 —— 能改配置的入口不该允许无限次猜。
- **只报有无**：接口只说「这个槽位有没有 key」，不回吐 key 本身。

口令在启动横幅里打出来，也存在 `state/console.token`。它跨重启保持不变，所以浏览器会话能活过重启；想换就删掉那个文件。

```
  控制台 http://127.0.0.1:27418/  （填槽位、改配额、签发 key）
  口令   CP5jJsFQ45yUZRBKuGW_tOPj
```

顺带修了一个启动横幅的老问题：重定向到日志文件时 stdout 是全缓冲的，整段横幅要等进程退出才出现。口令只显示这一次，晚出现的口令等于没有 —— 全加了 `flush=True`。

## 已知限制：保存后要重启

没有守护进程，网关做不到在进程内重启自己：端口还握在自己手里，重启出来的新进程会和它抢同一个端口。所以控制台只负责把配置写对、写安全，生效交给 `Ctrl+C` 之后的那条命令。界面上写明了这一点。

如果你希望「点一下自动重启」，需要引入一个最小化的重启协调（子进程等端口释放后再绑定，父进程退出）。这条路可行，但它引入的是进程管理问题，不是配置问题 —— 留到需要的时候再做。

## 其他

- `.env` 的读写抽成 `steward/envfile.py`，`init` 和控制台共用。两份实现必然会分叉：一份保留注释、一份不保留，一份 0600、一份 0644。
- `config_from_dict()` 从 `load_config()` 里抽出来，让「读配置」和「保存前校验」走同一套逻辑 —— 否则会出现界面验证通过、启动时却不认。
- 界面状态**以磁盘上的配置文件为准**，不是内存里那份。否则存完之后界面回显旧值，用户会以为没存上，再存一遍。
- 新增 `tests/test_console.py`（27 个）：注释保留、密钥分流、空值不覆盖、非法配置拒存、CSRF、限速、key 生命周期。

## 升级

```bash
git pull
python -m steward serve       # 打开 http://127.0.0.1:27418/
```

无需迁移。旧配置照样能跑，控制台会按你现有的文件显示。
